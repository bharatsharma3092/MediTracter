## 4. Database Schema (PostgreSQL via Prisma)

**File:** `backend/prisma/schema.prisma`

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"   // switch to "sqlite" for local/offline mode
  url      = env("DATABASE_URL")
}

model User {
  id           String       @id @default(cuid())
  email        String       @unique
  name         String
  createdAt    DateTime     @default(now())
  items        Item[]
  reorderLists ReorderList[]
  settings     UserSettings?
}

model UserSettings {
  id                String  @id @default(cuid())
  userId            String  @unique
  user              User    @relation(fields: [userId], references: [id], onDelete: Cascade)
  coverMonths       Int     @default(1)
  consumptionWindow Int     @default(30)   // rolling window in days: 30 | 60 | 90
  leadTimeDays      Int     @default(3)
  bufferDays        Int     @default(2)
  pushEnabled       Boolean @default(true)
  emailEnabled      Boolean @default(false)
  pushSubscription  String? // JSON string of PushSubscription object
}

model Item {
  id               String    @id @default(cuid())
  userId           String
  user             User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  name             String
  itemType         ItemType
  category         String
  unit             String
  currentQty       Float
  minQty           Float
  reorderQty       Float?
  expiryDate       DateTime?
  dosageSchedule   String?   // ONCE | TWICE | THRICE | AS_NEEDED
  prescriptionReq  Boolean   @default(false)
  storageCondition String?   // ROOM_TEMP | REFRIGERATED
  assignedTo       String?
  notes            String?
  createdAt        DateTime  @default(now())
  updatedAt        DateTime  @updatedAt
  stockLogs        StockLog[]
  alerts           Alert[]
}

model StockLog {
  id        String   @id @default(cuid())
  itemId    String
  item      Item     @relation(fields: [itemId], references: [id], onDelete: Cascade)
  date      DateTime @default(now())
  qtyChange Float    // positive = intake, negative = consumption/loss
  logType   LogType
  notes     String?
}

model ReorderList {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  generatedAt DateTime @default(now())
  items       Json     // snapshot array of ReorderListItem
  status      String   @default("draft") // draft | exported
}

model Alert {
  id          String    @id @default(cuid())
  itemId      String
  item        Item      @relation(fields: [itemId], references: [id], onDelete: Cascade)
  alertType   AlertType
  triggeredAt DateTime  @default(now())
  dismissed   Boolean   @default(false)
}

enum ItemType {
  MEDICINE
  EQUIPMENT
}

enum LogType {
  INTAKE
  CONSUMPTION
  EXPIRED
  DISCARDED
}

enum AlertType {
  LOW_STOCK
  EXPIRY_30
  EXPIRY_15
  EXPIRY_7
  REORDER_DUE
}
```

**Database Indexes (add to schema):**
- `Item`: index on `userId`, `itemType`, `expiryDate`
- `StockLog`: index on `itemId`, `date`
- `Alert`: index on `itemId`, `dismissed`

## 5. API Endpoints

Base path: `/api/v1`  
All routes are protected by `authMiddleware` except auth routes.

### Items
| Method | Path | Controller | Description |
|---|---|---|---|
| GET | `/items` | `itemController.list` | List all items; query params: `type`, `category`, `status`, `search`, `sortBy` |
| POST | `/items` | `itemController.create` | Create new item |
| GET | `/items/:id` | `itemController.getOne` | Get single item with recent stock logs |
| PUT | `/items/:id` | `itemController.update` | Update item fields |
| DELETE | `/items/:id` | `itemController.remove` | Delete item + cascade logs/alerts |
| GET | `/items/:id/reorder` | `itemController.reorderCalc` | Return live reorder calculation for one item |

### Stock Logs
| Method | Path | Controller | Description |
|---|---|---|---|
| GET | `/stock-logs/:itemId` | `stockLogController.list` | Get all logs for an item |
| POST | `/stock-logs` | `stockLogController.create` | Log intake or consumption; updates `item.currentQty` |
| DELETE | `/stock-logs/:id` | `stockLogController.remove` | Delete a log entry; reverses `item.currentQty` change |

### Alerts
| Method | Path | Controller | Description |
|---|---|---|---|
| GET | `/alerts` | `alertController.list` | Get all undismissed alerts for user |
| PUT | `/alerts/:id/dismiss` | `alertController.dismiss` | Dismiss single alert |
| PUT | `/alerts/dismiss-all` | `alertController.dismissAll` | Dismiss all alerts |
| POST | `/alerts/check` | `alertController.runCheck` | Trigger immediate alert evaluation for all user items |

### Reports
| Method | Path | Controller | Description |
|---|---|---|---|
| POST | `/reports/reorder` | `reportController.reorder` | Generate reorder list (items needing restock); saves to `ReorderList` |
| POST | `/reports/inventory` | `reportController.inventory` | Generate full inventory snapshot |
| GET | `/reports/history` | `reportController.history` | List past generated `ReorderList` records |
| GET | `/reports/:id/pdf` | `reportController.getPdf` | Server-side PDF generation fallback via Puppeteer |

### User / Settings
| Method | Path | Controller | Description |
|---|---|---|---|
| GET | `/users/me` | `userController.getMe` | Get user profile + settings |
| PUT | `/users/settings` | `userController.updateSettings` | Update cover months, consumption window, etc. |
| POST | `/users/push-subscribe` | `userController.subscribePush` | Save push subscription object |

## 7. Smart Reorder Calculation Logic

**File:** `backend/src/services/reorderService.ts`  
**Mirrored (pure functions):** `frontend/src/utils/reorderCalculator.ts`

```
Inputs per item:
  - stockLogs (last N days based on consumptionWindow setting)
  - currentQty
  - settings: coverMonths, leadTimeDays, bufferDays, consumptionWindow

Step 1: Filter logs of type CONSUMPTION within consumptionWindow days
Step 2: consumptionRate = totalConsumed / consumptionWindow   (units/day)
Step 3: daysOfStockLeft = currentQty / consumptionRate
Step 4: reorderTrigger = daysOfStockLeft <= (leadTimeDays + bufferDays)
Step 5: reorderQty = (consumptionRate × coverMonths × 30) − currentQty
Step 6: reorderQty = max(reorderQty, 0)  [never negative]

Output: { consumptionRate, daysOfStockLeft, reorderTrigger: boolean, suggestedReorderQty }
```

## 8. Alert Generation Logic

**File:** `backend/src/services/alertService.ts`

```
For each item belonging to user:
  - LOW_STOCK:   currentQty < minQty
  - EXPIRY_30:   expiryDate is within 30 days from today
  - EXPIRY_15:   expiryDate is within 15 days from today
  - EXPIRY_7:    expiryDate is within 7 days from today
  - REORDER_DUE: reorderTrigger === true (from reorderService)

Dedup logic:
  - Before inserting a new Alert, check if undismissed alert of same type+itemId exists
  - If exists: skip (do not create duplicate)
  - If not exists: create alert + call notificationService
```

## 9. PDF Export Strategy

### Client-side (primary):
**File:** `frontend/src/utils/pdfExporter.ts`

- Uses `jsPDF` + `jsPDF-AutoTable`
- `exportReorderPDF(items: ReorderListItem[])` — formatted table with header, date, item list
- `exportInventoryPDF(items: FullInventoryRow[])` — full stock snapshot
- Called from `hooks/useExport.ts`

### Server-side (fallback for mobile/low-memory):
**File:** `backend/src/services/pdfService.ts`

- Uses `Puppeteer` with a headless Chromium instance
- Renders an HTML template string → exports as PDF buffer
- Called by `reportController.getPdf` endpoint
- Frontend calls this endpoint if client-side PDF fails

## 10. Authentication Flow

1. User visits app → `App.tsx` checks `authStore.session`
2. No session → redirect to `/login`
3. `LoginPage.tsx` → calls `authService.ts` → Supabase `signInWithPassword` or social OAuth
4. Supabase returns JWT session → stored in `authStore` (Zustand persist → localStorage)
5. `api.ts` Axios interceptor reads `authStore.session.access_token` → sets `Authorization: Bearer <token>` header
6. Backend `authMiddleware.ts` → verifies JWT with Supabase public key → attaches `req.user = { id, email }`
7. All DB queries use `req.user.id` as `userId` filter (data isolation)

## 11. PWA Offline Strategy

**File:** `frontend/vite.config.ts` (vite-plugin-pwa)

- Service worker caches: app shell, static assets, API responses (stale-while-revalidate for GET /items)
- Offline reads: show cached inventory data
- Offline writes: queue mutations in IndexedDB, sync when back online (via Background Sync API)
- For full offline support, the frontend can optionally connect to a local SQLite API running on-device (Phase 2)
